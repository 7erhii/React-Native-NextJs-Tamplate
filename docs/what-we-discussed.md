# Что мы обсуждали и что строим

Это не ещё один README «как запустить». Это договорённость: **какой скелет клонируют**, какие кейсы он обязан закрывать, и чего в фундамент класть нельзя.

Репозиторий — **не один продукт**. Это основа, из которой получаются разные типы приложений: одностраничная мобилка, мобилка с аккаунтом, рекламный сайт с кнопкой Install, банк (сайт-кабинет + приложение на одной базе). Игра в хабе сейчас — пример плагина, не судьба скелета. Тудушки в обсуждении — тоже только пример.

---

## Зачем это вообще

Клон репы должен стартовать часами, не неделями. Оси, которые нельзя переписывать под каждый новый продукт:

1. **Телефон** — всегда. React Native / Expo.
2. **Сайт приложения** — опционально. Отдельный фронт, не Expo в браузере.
3. **База / аккаунты** — опционально. Включаются, когда продукту это нужно.
4. **Регистрация** — маркер на каждой поверхности (сайт и апп независимо), **не только строка в БД**.

Ошибка, которую скелет не должен повторять: запечь в фундамент один из кейсов (всегда Nest, всегда кабинет, всегда Expo-web «как сайт»).

---

## Четыре кейса (это продукт, не теория)

| | Сайт | Рега на сайте | Рега в аппе | База |
|---|---|---|---|---|
| **A** — одностраничная мобилка | нет | нет | нет | нет |
| **B** — только мобилка, но с регой | нет | нет | да | да |
| **C** — рекламный сайт + Install | да | нет (или только в аппе) | как нужно | обычно нет |
| **D** — «банк»: кабинет + апп | да | да | да | да |

Кейс **A** — дефолт репы. Клонул → `npm start` → телефон. Кабинета нет. Реги нет. Сайт не входит в поставку, пока флаг не включили.

Маркеры `web.auth` и `mobile.auth` **независимы**. Валидно: рекламный сайт без входа + залогиненная мобилка. Валидно: вход только на сайте. Валидно: оба.

Кнопка **Install** на сайте — поведение по умолчанию, когда `web.auth = false`. Кнопка **Sign in** на сайте появляется только если `web.enabled && web.auth`.

## Где живёт реги, если «не только из базы»

Переключатель: `packages/config/src/app.config.ts`.

```ts
web:    { enabled: false, auth: false }   // сайт + Sign in на сайте
mobile: { auth: false, authWall: 'none' } // Sign in в аппе + жёсткость стены
authSource: 'config'                      // позже: 'config+db'
```

- **Сегодня** флаги читаются из этого файла (и env). Сайт и апп оба его импортируют.
- **Потом** `authSource: 'config+db'` может наложить строку из базы **поверх** файла.
- Файл всё равно побеждает, если базы нет или она лежит. Регу нельзя «потерять», потому что Postgres выключен.

`mobile.authWall` (`none` | `optional` | `required`) — как жёстко апп закрывает home. Игнорируется, если `mobile.auth` выключен. Это не тот же флаг, что Sign in на сайте.

Google / email на Next **ещё не подключены**. Страницы `/sign-in` и `/sign-up` уже есть как реальные маршруты сайта, не как экраны Expo.

## Стек, который зафиксировали

| Кусок | Что | Зачем |
|---|---|---|
| `apps/mobile` | Expo 57, RN, Expo Router | телефон |
| `apps/web` | **Next.js** App Router | сайт приложения: реклама и/или кабинет |
| `packages/config` | один switch | оба клиента читают одни флаги |
| `infra/supabase` | Postgres + Auth + RLS | общая база, когда включена |
| идентичность / сохранения | порты + адаптеры | `local` / `cloud` / `hybrid`, `device` / `anonymous` / `google` |

Общее между сайтом и телефоном: **конфиг, типы, (потом) аккаунт в одной БД**.  
Не общее: UI. Экраны RN не шарятся в Next. Это модель банка, не Solito.

### Что отвергли и почему

| Идея | Почему нет |
|---|---|
| **NestJS как основа** | Свой сервер нужен, когда правда на сервере (биллинг, роли, античит). Для кейса A это процесс, который врёт «опциональности». Появится своя доменная логика — тогда отдельный сервис, не фундамент. |
| **Expo web = сайт приложения** | Это тот же клиент в браузере. У банка сайт — отдельный фронт с кабинетом, не `react-native-web`. |
| **Solito / Tamagui / общие экраны** | Противоположность банковской модели. |
| **Better Auth + tRPC как обязаловка** | Это продукт create-t3-turbo, не наш. Auth у нас — Supabase, когда включён. |
| **Кабинет в кейсе A** | Реги — маркер. Нет маркера — нет кабинета. |

NestJS **не запрещён навсегда**. Он решает «свой HTTP API с бизнес-правилами, которым нельзя доверять клиенту». Пока правила живут в RLS и в телефонах — он лишний.

## create-t3-turbo: что спиздили, что нет

Похож формой: монорепа `apps/*` + `packages/*` + Turbo + Next рядом с Expo.  
Не похож содержанием: Expo 54, Better Auth, tRPC, NativeWind, shadcn, TanStack Start вторым вебом, pnpm catalogs.

**Взяли**

- раскладка `apps/mobile`, `apps/web`, `packages/*`
- `turbo.json` (в т.ч. `globalEnv` на публичные ключи)
- Metro для монорепы: `watchFolders`, `nodeModulesPaths`, кэш `FileStore`
- раздельные UI у веба и телефона (у них Solito тоже нет)

**Не взяли**

- `packages/api` (tRPC)
- `packages/auth` (Better Auth) — у нас маркер + опциональный Supabase
- `packages/ui` (общий shadcn) — UI не шарим
- `packages/db` на Drizzle — SQL и RLS уже в `infra/supabase`
- NativeWind / pnpm catalogs / второй веб на TanStack Start
- «dev dependency tRPC только ради типов» — нет tRPC

Их tooling (`eslint`/`tsconfig` пакеты) — удобство большого шаблона. На трёх пакетах это жир. Можно добавить позже, если пакетов станет много.

## Как устроен клон

```text
apps/mobile     телефон (Expo). Вход: npm start
apps/web        сайт (Next.js). Вход: npm run web
packages/config ★ switch. Один файл меняет кейс
infra/supabase  база, когда persistence/identity/auth этого требуют
```

Дефолт (`app.config.ts` как в репе):

- `web.enabled = false`
- `web.auth = false`
- `mobile.auth = false`
- `identity.mode = 'device'`
- `persistence.mode = 'local'`

Это кейс **A**. Сайт всё равно можно поднять локально, пока его собираешь; в клон «не входит», пока флаг выключен.

Чтобы получить **C**: `web.enabled = true`, `web.auth = false`, кнопка Install.  
Чтобы получить **D**: сайт + оба auth + google + hybrid/cloud + живая база.

## Что уже стоит, чего ещё нет

**Уже**

- монорепа, switch, независимые маркеры реги
- Next-сайт: ленд, Install, Sign in / Sign up по `web.auth`
- мобилка без маркетингового маршрута (сайт — не экран Expo)
- порты identity/persistence, RLS-гейты, тесты конфига
- корневой `.env` (Expo и Next читают один файл; `EXPO_PUBLIC_*` ↔ `NEXT_PUBLIC_*`)
- EAS-заготовка: `apps/mobile/eas.json` (без `projectId`, пока не `eas init`)
- юрстраницы-заглушки `/privacy` и `/terms`
- иконки: контракт `IconName` в `packages/tokens`, телефон `expo-symbols`, сайт SVG
- Node: `engines` + `.nvmrc` 22 (RN 0.86 не поддерживает Node 23)
- Cursor-правило `.cursor/rules/skeleton.mdc`
- версия продукта: `packages/config/src/release.json` (Expo native + Settings + футер сайта)

**Потом, когда продукт этого потребует — не сейчас**

- Google / email на Next (страницы-заглушки уже на месте)
- overlay `config+db`
- настоящий кабинет (кейс D), не пустые кнопки
- NestJS / свой API — только если появится логика, которой нельзя доверять клиенту и RLS

## Как с этим жить

```bash
npm install
npm start     # кейс A: телефон
npm run web   # сайт на :3000, не Expo web
```

Переключатель: `packages/config/src/app.config.ts`.  
Constitution: `.specify/memory/constitution.md` (принцип III — реги как маркер поверхности).  
Добавить «игру»/фичу в апп: [`adding-a-game.md`](./adding-a-game.md) — тот же контракт плагина, даже если это тудушки, а не тапалка.
