# Дизайн-система: варианты

## Решение (2026-09-19)

**Вариант 1.** NativeWind на этот скелет не берём.

Проверка по твоему критерию («если в RN очень хорошо — 2, если костыли — 1»):

- **v5** в доке NativeWind прямо: *pre-release, not intended for production*. Нужны Tailwind 4, `react-native-css`, PostCSS, pin `lightningcss`, import rewrite. t3-turbo сидит на `nativewind@preview` — это не «хорошо работает».
- **v4.2.7** официально знает Expo 57, но это Babel `jsxImportSource` на всё дерево, Tailwind 3 (сайт на 4 не совпадёт), и апгрейды SDK уже ломали стили (54: css-interop версии, refs у Animated.ScrollView).
- Это **не полный Tailwind**. Третьи компоненты (Expo Image, шиты, @expo/ui) без `styled()`/`cssInterop` `className` не едят. Grid, часть теней, parent-state — дырки относительно веба.
- Next.js NativeWind всё равно не использует: общий кусок был бы только тема. Значит «один CSS-движок» — иллюзия; платишь NativeWind только на телефоне.
- Каждый клон наследует styling stack. Именно это `ui.tsx` уже отказывался навязывать.

Значит вариант 2 здесь — костыльный фундамент. Вариант 1: `packages/tokens` + свои примитивы + каталог в скоупе (`/ds`, UI kit).

---

Нужна заранее, чтобы компоненты и стили были **в скоупе** до фич: открыл каталог — увидел кнопку, поле, карточку, токены. Не выдумывать цвет на каждом экране.

Ограничение скелета, его нельзя сломать вариантом:

- сайт и телефон — **разный UI** (модель банка, не Solito);
- общее может быть только **язык** (токены: цвет, отступ, радиус, тип), не экраны;
- кейс A не должен тащить Storybook / Figma / Tailwind, чтобы открыть хаб.

Сейчас палитры уже разъехались: мобилка light/dark в `theme.ts`, сайт — тёмные CSS-переменные в `globals.css`. Акцент `#208AEF` совпадает, остальное нет. Компоненты есть кусками: `apps/mobile/src/components/ui.tsx` (Screen, Button, Card, Badge…) и классы на сайте (`.btn`, `.card`). Это не система, это два набора.

## Что значит «видно в скоупе»

Три разных «скоупа». Вариант ниже выбирает, какой из них главный.

| Скоуп | Что видишь | Когда открывается |
|---|---|---|
| **В репе** | страница `/ds` на сайте + экран UI kit в мобилке | `npm run web` / `npm start` |
| **В Figma** | library: variables с правильным scope (fill / text / stroke), компоненты с вариантами | файл дизайн-системы |
| **В Storybook** | изолированные стори | отдельный девсервер |

Для скелета достаточно **репы**. Figma — когда появится дизайнер или надо шарить макеты. Storybook — когда компонентов станет десятки и `/ds` тесно.

## Три варианта архитектуры

### 1. Токены общие, компоненты свои, каталог в приложениях

`packages/tokens` — цвета, spacing, radius, type, elevation. JSON/TS, без React.

- `apps/web` мапит токены в CSS variables.
- `apps/mobile` мапит те же токены в `theme.ts`.
- Примитивы пишутся **дважды**, но по одному контракту: `Button`, `Text`, `Card`, `Field`, `Badge`, `Page`.
- Каталог: `apps/web/src/app/ds` и мобильный экран `ui-kit` (за diagnostics-флагом).

**Плюс:** не ломает банк-модель; кейс A живёт; токены видны в обоих клиентах; каталог — часть продукта-скелета.  
**Минус:** кнопку правишь в двух местах. Это плата за разные платформы, не баг.

Это вариант по умолчанию для этого репо.

### 2. Один CSS-движок на обе стороны (NativeWind + Tailwind)

Как create-t3-turbo: `tooling/tailwind` + NativeWind в Expo, Tailwind в Next. Токены — в `@theme` CSS.

**Плюс:** один className-язык, меньше дублирования утилит.  
**Минус:** NativeWind v5 preview, навязанный styling stack на каждый клон, сайт и телефон начинают выглядеть как один HTML. Мы это уже отвергли как фундамент. Имеет смысл только если сознательно хочешь «вебовый» UI на телефоне.

Не брать, пока не скажешь «хочу Tailwind везде».

### 3. Figma — источник правды, код подтягивает

Сначала library в Figma (variables + компоненты), потом код и Code Connect. Каталог «в скоупе» — Figma, не `/ds`.

**Плюс:** дизайнер и агент смотрят один файл; scopes у variables работают как надо.  
**Минус:** без Figma-файла скелет не самодостаточен; кейс A обрастает внешним артефактом. Делать **после** варианта 1, как зеркало, не вместо.

## Что прописать в v1 (узкий скоуп)

Не дизайн-система Material. Набор, без которого нельзя собрать ленд, вход и хаб.

**Токены**

- color: `bg`, `bg-elevated`, `text`, `text-muted`, `accent`, `danger`, `warning`, `success`, `line`
- space: 4 / 8 / 16 / 24 / 32 (как уже `Spacing`)
- radius: 8 / 12 / 16 / pill
- type: heading, subheading, body, caption, label
- theme: light + dark (сайт сейчас тёмный-only — выровнять)

**Компоненты (контракт одинаковый, реализация своя)**

| Компонент | Зачем заранее |
|---|---|
| Button `primary / secondary / ghost / danger` + disabled/busy | CTA, вход, деструктивные действия |
| Text `heading / sub / body / muted / kicker` | не плодить fontSize на экране |
| Field (label + input + error) | реги на сайте и в аппе |
| Card | хаб, ленд, кабинет потом |
| Badge | статусы, durability |
| Page / Screen | отступы и ширина |
| Header (бренд + actions) | сайт уже почти это |
| Avatar | профиль |

Состояния сразу: default, pressed/hover, disabled, error. Иначе каталог врёт.

**Не в v1:** модалки, тосты, датапикер, таблица, навигация кабинета, иконпакет. Появятся с фичей.

---

## Как каталог не протечёт в кейс A

- Веб-маршрут `/ds` есть всегда в коде сайта, но сайт не шипится, пока `web.enabled = false`. Для разработчика `npm run web` всё равно открывает каталог.
- Мобильный UI kit — за `features.diagnostics` (уже есть). В проде клона с `diagnostics: false` экрана нет.
- Figma / Storybook — опциональные артефакты, не dependency `npm start`.

## Рекомендация

Взять **вариант 1**. Порядок:

1. `packages/tokens` + выровнять сайт и телефон на одну палитру.
2. Контракт примитивов (имена/варианты) в доке, реализация в каждом аппе.
3. Каталог `/ds` и UI kit — чтобы «было видно в скоупе».
4. Потом, если надо, зеркало в Figma из этих токенов.

Вариант 2 — только по явному «Tailwind везде».  
Вариант 3 — второй шаг, не первый.
